## 2. Стилистика

### Направление: точный векторный атлас

Сдержанная картографическая графика, ясная иерархия подписей, светлая нейтральная подложка. Форма, пропорции, штриховка, направление, разрывы и модификаторы каждого знака воспроизводятся по эталону. Общая сетка организует каталог, но не меняет пропорции знаков.

- Каждый знак — редактируемые векторы; текстовые поля остаются текстом. Скан служит материалом сверки, а не готовым компонентом.
- Фон символа прозрачный. Белая подложка допустима внутри знака только по источнику; фон карточки является отдельным слоем.
- Тени, градиенты, объём, эмблемы и декоративные детали к знакам не добавляются.
- Окончания линий, углы, толщина и интервалы штрихов повторяют источник. Геометрические модификаторы не заменяются похожими буквами шрифта.
- Цвет принадлежности и специальные цвета задаются только после проверки документа. Цвета существующего режима DALA не объявляются стандартом ВС РК.

### Оформление атласа — значения проекта

Эти значения относятся к оболочке справочника, а не к военному стандарту.

| Параметр | Значение |
|---|---|
| Фон листа | `#F7F7F5` |
| Фон карточки | `#FFFFFF` |
| Основной текст | `#242424` |
| Вторичный текст | `#606060` |
| Разделители | `#DDDDD8`, 1 px |
| Фон образца карты | `#E8ECE4`, из DALA |
| Шрифт справочника | Inter; при отсутствии — Arial |
| Заголовок / раздел / название / метаданные | 32/40, 22/28, 14/20, 12/16 px |
| Шаг отступов | 4, 8, 16, 24, 32, 48 px |
| Карточка | 320 px шириной, высота по содержимому, отступ 24 px |
| Обзорный лист раздела | 1440 px, поля 48 px, 4 колонки, промежутки 24 px |

Точечные знаки показывать в демонстрационном поле 64×64 px; проверять читаемость при 32, 48 и 64 px. Линейные образцы показывать в поле 240×80 px, площадные — 240×160 px. Масштабировать равномерно с сохранением места для подписей. Размеры полей — демонстрационные, не размеры объектов на местности. Мелкую графику увеличивать, если иначе теряются значимые детали.

Цвета `#BC3434`, `#245CB5`, `#242424` разрешены только в отдельном сравнении с текущей учебной системой DALA. Официальные цветовые роли добавлять в библиотеку вместе с подтверждением; если документ задаёт цвет словом, выбранный цифровой оттенок помечать как интерпретацию для экрана.

Подписи каталога — русские, как на `/symbols`. Официальное название хранить отдельно, если оно отличается. Казахские названия добавлять только из проверенной казахской версии источника. Терминологию и тактические сокращения не переводить автоматически.

## 3. Источники и проверка

Для каждой записи реестра нужны: исходный ID DALA, название из каталога, название по документу, геометрия, URL, название и редакция документа, страница/приложение/рисунок, область применения, статус сверки и примечания. Для HTML вместо страницы указывать приложение, таблицу и строку. При отрисовке сохранить ссылку на конкретный просмотренный рисунок.

Статусы:

- `pending` — проверка не завершена; символ в официальной библиотеке отсутствует.
- `verified` — просмотрен первичный рисунок, установлены источник и применимость для соответствующей записи.
- `conflict` — источники расходятся или применимость неоднозначна; рисунок не публикуется как подтверждённый.
- `not_found` — поиск по записи завершён, достаточного подтверждения не найдено.

Первичный источник должен подтверждать именно обозначение и его назначение. Учебные материалы военной кафедры могут дать направление поиска, но сами по себе не доказывают утверждение знака для ВС РК. Совпадение названия объекта также недостаточно. Полигонные знаки, знаки МВД и топографические обозначения не переносятся в общий тактический каталог без подтверждения области применения.

### Результат предварительного поиска

1. [Приказ МО РК от 06.12.2022 № 1171: правила деятельности полигонов и учебных центров](https://www.adilet.zan.kz/rus/docs/V2200031067/info). Карточка документа найдена. Поисковая выдача указывает на приложение 12 с обозначениями мишеней и объектов авиационных полигонов. Это кандидат для предметной проверки; рисунки и соответствия 231 позициям ещё не проверены. Прямое чтение полного текста в текущей сессии было нестабильным.
2. [Тактико-специальная подготовка, программа КазНУ](https://pps.kaznu.kz/ru/Main/FileShow/2102386/119/446/4099/%20%20%20%20%20%D0%A8%D0%BE%D0%BF%D0%B0%D0%B1%D0%B0%D0%B5%D0%B2%D0%91%D0%B0%D1%82%D1%8B%D1%80%D0%B1%D0%B5%D0%BA%D0%90%D0%B1%D0%B5%D0%BD%D0%BE%D0%B2%D0%B8%D1%87/2013/2). Упоминает тактические знаки для оперативно-служебных документов ОВД. Не использовать как подтверждение стандарта ВС РК.
3. [Исторический материал, используемый DALA](http://lemur59.ru/node/427) и три локальные таблицы в `public/reference/`. По документации проекта относятся к Советской Армии. Использовать для сопоставления состава каталога, но не для присвоения статуса `verified`.

Единый подтверждённый альбом ВС РК на все 231 позиции пока не найден. Это результат предварительного поиска, а не утверждение об отсутствии такого документа. В реестре сейчас все позиции имеют `pending`; число подтверждённых знаков — 0.

Для дальнейшего поиска: точное название записи и его сокращения, документы МО РК и военных учебных заведений, затем проверка титульного листа, редакции, рисунка и применимости. Если первичный документ недоступен или рисунок нечитаем, оставить статус `pending` с причиной. После завершённого поиска без результата установить `not_found`. Не назначать всем записям один найденный источник автоматически.

## 4. ТЗ для Figma

### Подключение и размещение

Использовать локальный Figma Desktop Bridge из `Documents/figma mcp/figma-console-mcp-1.31.0/figma-desktop-bridge`. Перед работой получить успешный `figma_get_status({probe:true})`, список подключённых файлов и проверить ключ `xETgV3IcGzOILAB8vPHxky`.

На момент подготовки сервер запущен на порту 9225, подключённых файлов нет. Нужно перезапустить плагин в Figma. Содержимое узла `1:2` и существующие стили файла ещё не прочитаны. Ранее REST-доступ возвращал `Token expired`; Desktop Bridge должен работать независимо от REST-токена.

После подключения прочитать целевой узел, его страницу, существующие компоненты, переменные и стили; сделать снимок страницы. Создать на этой странице отдельную секцию `DALA / Тактические обозначения РК` ниже существующего содержимого с зазором 160 px. Узел `1:2` использовать как ориентир страницы, не заменять его содержимое. Повторный запуск продолжает созданную секцию по сохранённым ID. Не создавать новый файл.

### Состав секции

1. `00 / О библиотеке` — назначение, версия, охват и число подтверждённых позиций.
2. `01 / Правила оформления` — типографика, образцы размеров, проверенные цвета и правила нанесения.
3. `02 / Источники и реестр` — все 231 записи со статусами и ссылками.
4. `03 / Компоненты` — подтверждённые символы, сгруппированные по 10 разделам.
5. `04 / Атлас` — обзорные листы тех же 10 разделов; подтверждённые знаки представлены экземплярами компонентов.
6. `05 / Проверка на карте` — образцы на белом, приглушённом картографическом и тёмном фоне.

В атласе показывать все записи. Для неподтверждённых — название, ID и текст «Источник не подтверждён», без условной пиктограммы. Такие карточки не экспортировать как символы. При частичном покрытии показывать счётчик `подтверждено N из 231`.

### Компоненты и свойства

- Имя базового компонента: `RK/<category>/<catalog-id>`. Название и источник — в описании. ID DALA сохраняются без переименования.
- Векторы символа, обозначение уровня и подписи — отдельные слои. Для типов без уровня подразделения это свойство отсутствует.
- Свойства принадлежности, уровня и состояния создавать только для вариантов, подтверждённых источником. Не перемножать все 7 уровней на все 231 записи.
- Пользовательские номер и название — текстовые свойства; скрытие подписи — boolean; замена подтверждённого вложенного символа — instance swap.
- Линейные и площадные компоненты содержат редактируемые пути и отдельные модификаторы. Увеличение образца не должно растягивать пиктограммы и толщину линий; форма конкретного маршрута редактируется по векторным узлам. Автоматическое размещение вдоль произвольного пути в эту версию не входит.
- Примитивы, семантические цвета и стили текста создать до компонентов. Цвета знаков привязывать к отдельным подтверждённым семантическим ролям. Стили справочника не задают принадлежность войск.
- Сетки и карточки собирать через Auto Layout. Компоненты размещать внутри именованных контейнеров. Исходные векторы сохранять редактируемыми.
- В описании компонента хранить человекочитаемую ссылку на источник и область применения. Технический журнал созданных ID хранить отдельно от Figma-объектов.

### Выгрузка и границы изменений

Подготовить SVG для подтверждённых символов с прозрачным внешним фоном и стабильными именами `<catalog-id>--<variant>.svg`. Сохранить таблицу соответствия `catalog-id → Figma node ID → SVG → источник`. Подписи источников и карточки не включать в SVG знака. Приложение, игровые характеристики и публичные API не менять.

## 5. Порядок работы и приёмка

1. Восстановить Bridge, прочитать файл и сверить возможность размещения.
2. Заполнить реестр источников; для каждого подтверждённого знака зафиксировать разрешённые варианты.
3. Создать основы оформления и структуру секции.
4. Сделать пробную серию из подтверждённых точечных, линейных и площадных знаков. Если какая-то геометрия пока не подтверждена, показать её текстовый статус и продолжить доступную часть.
5. Последовательно собрать компоненты и листы по разделам. После каждого раздела проверить снимок и исправить найденные дефекты.
6. Проверить реестр, варианты, экспорт и финальный обзор секции. Опубликовать результат с точным числом подтверждённых и оставшихся позиций.

Критерии приёмки:

- В реестре ровно 231 уникальный ID, количества разделов и геометрий совпадают с исходным каталогом.
- Каждый опубликованный символ имеет просмотренный эталон, ссылку и точный локатор; неподтверждённые позиции явно отмечены.
- На масштабе 100% и при увеличении нет пропавших деталей, наложений подписей и обрезанных штрихов. В 32 px не исчезают смысловые элементы; иначе указан больший минимальный размер.
- Принадлежность, уровень, направление и состояние совпадают с подтверждённым источником. Тестовые образцы не используются для генерации неподтверждённых сочетаний.
- Экземпляры связаны с компонентами, векторы редактируются, текстовые свойства работают, переменные разрешаются.
- Все три типа геометрии проверены на указанных фонах. Проблемы контраста решаются на уровне подложки интерфейса с отдельной пометкой, без незаметной смены семантического цвета знака.
- SVG открываются без обрезки, имеют корректный `viewBox` и совпадают с образцом Figma.
- Существующее содержимое файла не перекрыто; нет пустых дубликатов и технических слоёв.

ТЗ допускает частично заполненную официальную библиотеку и полный реестр пробелов. Оно не допускает выдавать 231 записи реестра за 231 проверенный официальный знак.
